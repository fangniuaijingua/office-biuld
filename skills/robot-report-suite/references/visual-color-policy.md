# 报告中的少量彩色图片策略

## 基本分工

实验报告的技术逻辑由黑白文字、表格、流程图、结构图和曲线承担；彩色图片只补充实物、场地、视觉系统画面或用户给出的固定模板素材。不要把报告改造成 PPT，也不要让颜色成为状态、优先级或结果的唯一编码。

## 允许范围

1. 默认保留模板原有的彩色校徽、logo、官方插图和用户提供照片；不重新着色。
2. 对八页左右的报告，通常最多新增 1—2 张彩色图片，或使新增彩色图片的总版面不超过新增图形面积的约 20%。用户指定的模板或课程要求优先。
3. 允许的新增彩色图片：已知来源的实物/现场照片、相机原始画面、用户确认的屏幕截图，或清楚标为“解释示意，非实测”的生成图。
4. 禁止的新增彩色内容：彩色文字、彩色底纹、渐变卡片、装饰色块、无来源的性能曲线、彩色流程/状态卡，以及会使数据只能靠红绿等颜色辨认的图。

## 单图登记与图注

每张新增彩色图都在 `manifest.json` 或图形卡片中记录：

```text
图号：
类型：原始彩色证据图 / 解释示意图
原始文件或生成提示词：
来源与时间：
能证明：
不能证明：
本报告新增彩色图序号：n / 总预算：
```

图注要写明材料身份，例如“图 4-2 车载相机原始画面（用户提供）”或“图 5-1 协同场景解释示意（生成图，非实测）”。如果图片来自生成工具，不能生成可读的仪表数值、实验结果、校徽或现场认证标志。

## 版式与验收

- 彩色图片用于一个明确的观察点；相邻页不要连续堆放同类彩照。
- 保持原始纵横比，必要时只裁去无关背景；不得美化或重画测量读数、识别框、日志内容。
- 图内外仍使用黑色图题和正文；彩照旁配黑白流程图、表格或文字说明，确保灰度打印时结论仍然可读。
- 格式审计除彩色字体/底纹外，还检查彩色图的数量、来源与证据边界；不满足时改为黑白、删除或降级为待补材料。


## 模板继承下的低彩度默认值

- “尽量少蓝色”是新增内容的默认偏好，不等于授权将整份模板强制黑白化。模板明确要求的颜色、校徽、固定信息页和图片保持原样；只有明确要求全篇黑白时才选 strict_monochrome_override。
- 没有明确颜色要求时，新增正文、标题、图题、表题、表内文字用黑色；表格用白底黑/灰线，必要分组可用浅灰。不要自动套用 Word 的蓝色 Heading、Accent 表头或蓝色超链接外观；链接可保留功能，显示格式按格式契约。
- 字体、字号、行距、缩进与表头字重先继承实际模板/学校规范，包括中文、英文数字和公式字体。不得因“高级感”换成统一品牌字体；无指定样式时才使用技能原有论文默认值。
- 审稿时区分“模板要求保留的蓝色”和“新增主题样式引入的蓝色”。检查直接格式及样式继承的最终渲染效果，后者无依据则改为黑白/灰阶；不要误改原始数据图片。


## 技术插图的色彩面积

允许图片有色彩，不等于所有技术框图默认铺蓝色。新建或获准修改的架构、流程与地图图优先白底、黑/深灰文字、灰线；需要区分区域时使用小面积、低饱和的暖灰、米色或低饱和棕色。色彩服务语义，不靠逐框换色制造区分。大面积地图底色应近白、网格弱化，路径与安全裕量保留必要对比；实拍与数据图片不得为去蓝而改动其证据内容。用户指定模板或语义配色仍优先。

## 黑白 / 棕色技术图与彩照的区别

技术图默认黑白/灰阶；非严格黑白要求下，可按格式契约采用少量低饱和棕色线条、浅米色安全裕量或局部标题底，不把整张图铺成棕色卡片墙。正文、表格和图题仍按模板字体及黑白要求执行。前述禁止彩色底纹主要约束 Word 正文/表格和装饰性状态卡，不否定这一明确登记的技术图例外。strict_monochrome_override 下不使用棕色技术标注。

彩色实拍/现场/相机图片保留必要原色，以少量、证据相关为准；8页左右通常1—2张仅为预算起点，不按每页配额机械安排，也不为减少色彩篡改原图读数。灰度打印时仍须通过线型、标签与位置理解图意。
